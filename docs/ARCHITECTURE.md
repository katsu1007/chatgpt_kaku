# KAKU NEXT — Architecture & Change Safety

## 1. 現状の主要モジュール

| 領域 | 主なファイル | 役割 |
|---|---|---|
| 起動・状態・保存 | `js/main.js`, `js/app.js`, `js/store.js`, `js/sync.js`, `js/undo.js` | 起動、画面遷移、案件保存、同期、Undo/Redo |
| 数量・金額計算 | `js/calc.js`, `js/master-data.js` | 部屋形状、開口控除、数量、ロス、原価等 |
| 案件・画面 | `js/project.js`, `js/pages.js`, `js/home.js`, `js/ui.js` | 案件編集、各画面、共通UI |
| 図面・作図 | `js/cad.js`, `js/drawing.js`, `js/planview.js`, `js/sketch.js`, `js/sketchui.js`, `js/roomfin.js` | 図面表示、作図、部屋候補、手書き図面補助 |
| 図面読取 | `js/reader2/`, `js/kaku-engine.html` | 図枠・文字・線・区画候補の解析 |
| 電気・設備 | `js/elec.js`, `js/lighting.js`, `js/piping.js`, `js/place.js` | 電気・照明・配管・器具配置 |
| 3D・床 | `js/view3d.js`, `js/floors.js` | 3D表示、床関連 |
| 帳票・出力 | `js/docs.js`, `js/export.js` | 帳票、CSV等の出力 |
| テスト | `tests/*.test.mjs` | 計算・読み取り等の回帰確認 |

## 2. 変更の原則

1. 計算ロジックを画面コードへ重複実装しない。数量計算は原則 `js/calc.js` に集約する。
2. 図面解析結果と人が確定した情報を区別する。自動認識は候補・信頼度・根拠を保持する。
3. 既存案件データのキーや意味を変える場合は、旧データの読み込み・移行テストを先に用意する。
4. 保存成功の表示は、対象データ一式の保存完了を確認してから行う。
5. 画面変更では iPhone幅、PC幅、タッチ操作、キーボード表示時を確認する。
6. 図面エンジンや大きな統合ファイルを変更する場合、変更範囲・入力形式・出力形式を記録し、代表図面で比較する。

## 3. 削除してはいけないもの（確認前）

- `old/`：旧版保管の可能性があるため、現行コードからの参照・復旧用途を確認するまで削除禁止。
- `js/kaku-engine.html`：大きな統合エンジン。画面からの呼び出しと機能範囲を調べずに削除・分割しない。
- `vendor/`：PDF.js / Three.js の同梱物。ライセンスと利用箇所を確認せず削除しない。
- `js/master-data.js`：工事項目・単価等の重要データ。整理時もIDと既存案件への互換性を維持する。
- `CLAUDE.md`：開発時の指示書。重複・古い記述を精査してから整理する。

## 4. 完了条件

機能を「実装済み」とするには、少なくとも以下を満たすこと。

- 実際の画面から操作できる。
- 保存後に再読込して状態が残る。
- 関連する自動テストが通る。
- 既存案件データを壊さない。
- 未対応条件・誤差要因・人による確認箇所を明記する。
